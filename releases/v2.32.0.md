# v2.32.0 — 2026-11-16


## Overview

This release adds organization API keys and task artifact details. It also corrects branch resolution, upload cleanup, GitLab merge-request lookup, and task health behavior.

## Breaking Changes

- **Task label names.** Duplicate task label names now return `409 TASK_LABEL_NAME_CONFLICT` instead of a server error. Clients that expected the old error should handle the conflict.

## By the Numbers

- **Changes.** This release touched 165 files with 5,992 added lines and 1,592 deleted lines.
- **Testing.** The release reported 18,580 tests, with 18,580 of 18,580 completed. Pass/fail status was not supplied.
- **Line coverage.** Line coverage for the measured scope is 86.84%, with 76,631 of 88,245 lines covered.

## Added

- **Task artifact details.** Open an artifact page by id: `GET /tasks/artifacts/{id}` returns size, type, date, project, task, and a download link.
- **Organization API keys.** Call organization APIs with branded `sk_syn_…` keys in `Authorization: Bearer` or `X-API-Key`; the key acts as its creator’s organization role, never as platform superadmin.

## Changed

- **Upstream default branch.** When a repository source has no saved branch, the platform now reads the live upstream default branch, so `default_branch` reflects the current project state instead of an empty value.
- **Upload cleanup.** New abandoned uploads are expected to clear in 2–3h instead of 48–72h, and projects now limit active uploads per user.

## Fixed

- **GitLab merge requests.** Publishing tasks no longer gets stuck when a merge request exists; an open merge request is found immediately instead of scanning old history.
- **Task health.** The platform no longer reports degraded task health from normal upload conflicts, and lock-related upload errors are fixed.
